# Security Reporting

If you find a security issue in D & J's Karaoke Software, report it privately to the repository owner before opening a public issue.

## What to report privately

- Credential, token, or secret exposure.
- Personal singer information exposure.
- Unauthorized access to catalog, venue, host, or request data.
- Any workflow that could allow unapproved media storage or distribution.
- Any behavior that could interrupt a live show unexpectedly.

## Public issue guidance

Public issues are fine for non-sensitive bugs, documentation gaps, and feature planning. Do not include secrets, private URLs, venue network details, real karaoke files, or personal singer information in public issues or pull requests.

## Current security posture

Wave 0A contains documentation and placeholders only. Authentication, authorization, data retention, audit logging, and production security controls are future backlog work and must be designed before production use.
